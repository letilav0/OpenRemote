An agent can drive a real browser, and the console stops claiming things it has not checked.

OpenRemote is one window for the agent harnesses on your computer - Claude Code, Codex, grok, pi, opencode, agy. This release brings the built-in browser into the product properly: pages live in a pane beside the chat, and the chat's agent can open, read and click them through its own tools.

## The browser, and how to use it

**Open the pane.** Four ways, all the same pane:

- the **Browser** tile in the sidebar, beside Plugins and Automations;
- **Ctrl+Shift+B** (the shortcuts sheet lists it as "Show or hide the browser");
- the globe in the floating icons at the top right;
- the command palette: **Ctrl+K**, then "Show or hide the browser".

The pane sits at the right of the window, beside the chat, and keeps its tabs when you close it.

**What it is.** Chrome's arrangement on this machine's own engine: a tab strip, an address bar, back and forward, find, print, DevTools in a dev build. Pages are WebView2 on Windows and WebKit elsewhere, in a profile of their own, so they never share storage with the console. No bundled Chromium is downloaded.

**How an agent uses it.** Every chat's harness is started with OpenRemote's own MCP server, and that server now carries the browser's tools: open a tab, navigate, read a page as text, click, type, press keys, hover, scroll, pick an option, wait for text, take a screenshot, read the console and network, run a script, upload a file from the chat's folder. An agent finds them itself; you can simply ask for what you want ("open the docs page and tell me what the install steps are") or say "use the browser".

**Who holds the page.** A tab an agent opens is drawn off screen until you show it, and marked with its chat. While an agent holds a tab, your own click takes control back, and the agent is told. A **private** tab is kept from agents and history until you hand it over.

**What it will not do.** Uploads only come from the chat's own folder. A page's downloads are refused unless they pass the browser's policy, because the pane is drawing a window that runs your agents. Pages cannot reach the app's own addresses.

## The console stops telling you things it has not checked

- **A saved setup settles silently.** Pressing a setup whose model or project is gone applies what it still can and says nothing about the difference.
- **The numbers match the lists.** Metrics counts the active chats, names a state it cannot classify instead of dropping it, and a "ran" line no longer invents a time for a stamp in the future.
- **The changes surface says what it could read**, and counts only reports that landed.
- **Pairing counts down honestly**, and a phone list it could not read says so.
- **An endpoint's address is printed without the credentials in it.**
- **Privacy mode covers the settings search.** Compact density says which surfaces it changes.
- **A refused write says so**: archiving, and a copy the clipboard refused.
- **Two projects that read the same name say which folder they are**, a project whose folder is gone is drawn as what it is, and a project list that failed to load no longer reads as a machine with no projects.
- **The phone's own screen stops addressing a desktop user**, its device card looks openable without a hover, and a failed account read says the Cloud did not answer.

## Keys, dialogs and the dropdown

Escape in a field outside the chat no longer interrupts the turn. A dialog hands the keyboard back to the control you actually pressed. The dropdown behind every picker keeps its keyboard, takes the press it consumed, and re-clamps when the window shrinks.

## The client and the data loop

A timeout carries a status, an install has a ceiling again, and a success whose body could not be read is an error rather than an empty answer. Pointing the console at another daemon no longer keeps the old one's chats. The fold announces an event it cannot read instead of redialling for ever, and a stream the daemon keeps refusing stops and leaves its words in the transcript.

## Known

- An installed app still does not look for a newer version. Moving to a newer release means running a newer installer over it, or `openremote --update` if you installed through npm.
- The browser's pane is not on a phone; a phone lists and drives chats, not tabs.
