An agent can drive a real browser, and the console keeps the pages you read.

This is 0.4.4 and 0.4.5 together. 0.4.4 was tagged but never reached the
download page: its Linux and macOS builds failed on a dependency that was
declared for Windows only, so the browser that release described was never
published anywhere. The builds compile, and this is that release with the
night after it folded in: the browser's bookmarks, its history and its
suggestions, and a set of fixes where the console had been telling you
something it had not checked.

OpenRemote is one window for the agent harnesses on your computer - Claude
Code, Codex, grok, pi, opencode, agy - and the built-in browser is part of the
product now: pages live in a pane beside the chat, and the chat's agent can
open, read and click them through its own tools.

## The browser, and how to use it

**Open the pane.** Four ways, all the same pane: the **Browser** tile in the
sidebar, beside Plugins and Automations; **Ctrl+Shift+B** (the shortcuts sheet
lists it as "Show or hide the browser"); the globe in the floating icons at the
top right; or the command palette, **Ctrl+K** then "Show or hide the browser".
The pane sits at the right of the window, keeps its tabs when you close it, and
its width is yours to drag.

**What it is.** Chrome's arrangement on this machine's own engine: a tab strip,
an address bar, back and forward, find, print, DevTools in a dev build. Pages
are WebView2 on Windows and WebKit elsewhere, in a profile of their own, so they
never share storage with the console. No bundled Chromium is downloaded.

**How an agent uses it.** Every chat's harness is started with OpenRemote's own
MCP server, and that server carries the browser's tools: open a tab, navigate,
read a page as text, click, type, press keys, hover, scroll, pick an option,
wait for text, take a screenshot, read the console and network, run a script,
upload a file from the chat's folder. A tab an agent opens is drawn off screen
until you show it and is marked with its chat; your own click takes control
back, and the agent is told. A **private** tab is kept from agents and history
until you hand it over.

**What it will not do.** Uploads only come from the chat's own folder. Pages
cannot reach the app's own addresses. A page's downloads land in your Downloads
folder, and the console keeps one row per download with its own id, so two of
them are never confused.

## Reading, kept

- **Bookmarks.** The star beside the address bar, or **Ctrl+D**, keeps the page
  on the bookmarks bar and opens a small editor for its name and folder. The
  same press on a kept page edits that bookmark instead of making a second one,
  so an address is always one row. A bookmark with no name is drawn as its
  address, and the bar appears only while something is kept.
- **History.** Grouped by the day it happened, newest first, five hundred pages
  per window, opened from the pane's own menu. A row opens its address, and
  Clear history asks once before it empties.
- **Suggestions.** Typing into the address bar ranks one address once: a title
  that starts with the letters beats the same letters inside a title, a kept
  bookmark beats a plain visit of the same quality, and the newer visit comes
  first among equals. The arrows move the highlight and Enter opens it, with the
  field keeping the focus.
- All three stay on this computer. Nothing about your reading is sent anywhere,
  and none of it needs an account.

## The console stops telling you things it has not checked

- **A saved setup settles silently.** Pressing a setup whose model or project is
  gone applies what it still can and says nothing about the difference.
- **The numbers match the lists.** Metrics counts the active chats, names a state
  it cannot classify instead of dropping it, and a "ran" line no longer invents a
  time for a stamp in the future.
- **Cost and thinking tokens were counting twice.** The daemon re-reports a
  turn's usage when a stream reconnects, and the console had no way to tell that
  turn from a new one, so the row doubled. Both payloads now name their turn,
  and a repeated report replaces its own tally instead of adding to it.
- **A picker can always be searched.** Typing into any dropdown threw when a
  caller's row had no name yet, which is every list while it loads.
- **The dropdown keeps its keyboard**, takes the press it consumed, and
  re-clamps when the window shrinks. A dialog hands the keyboard back to the
  control you actually pressed.
- **A refused write says so**: archiving, and a copy the clipboard refused.
- **Two projects that read the same name say which folder they are**, and a
  project list that failed to load no longer reads as a machine with none.

## Known

- An installed app still does not look for a newer version. Moving to a newer
  release means running a newer installer over it, or `openremote --update` if
  you installed through npm.
- The browser's pane is not on a phone; a phone lists and drives chats, not tabs.
- Bookmarks and history do not follow you to another computer yet. They are this
  device's, on purpose for now; the account carries chats and machines.
